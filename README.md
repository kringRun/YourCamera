# VisionCore

C# 12 / .NET 8.0 / WPF 工业视觉模块初版。使用支持 .NET 8 的 Visual Studio 和“.NET 桌面开发”工作负载，或 .NET 8 SDK。桌面程序运行需要 .NET 8 Windows Desktop Runtime（x64）。

```powershell
dotnet build YourCamera.sln
dotnet run --project src/Vision.Desktop
```

核心、采集和验证项目目标为 `net8.0`，WPF 项目目标为 `net8.0-windows`，语言版本统一为 C# 12。`YourCamera.sln` 可用于 .NET 8 SDK；`YourCamera.slnx` 保留供支持该格式的较新开发工具使用。`global.json` 优先选择兼容的 .NET 8 SDK，本机缺少时允许使用更高主版本 SDK 编译，生成程序的运行时目标仍为 .NET 8。SDK 选择与运行时目标是不同设置，参见 [Microsoft SDK 选择说明](https://learn.microsoft.com/en-us/dotnet/core/tools/global-json)。

## 项目

- `Vision.Core`：灰度图像、旋转矩形卡尺、极性与阈值设置、直线总最小二乘拟合、圆的最小二乘拟合、直线交点、无向锐夹角与两点距离、JSON 流程定义和依赖并行执行器。
- `Vision.Acquisition`：`ICamera` 适配接口、模拟相机，每台相机独立的采集任务和处理任务。容量为 2 的有界通道满时丢弃最旧图像，适合实时预览。每帧持有独立托管像素数组。
- `Vision.Communication`：SocketServer TCP 服务、通讯配置保存、多客户端连接、UTF-8 换行消息收发、连接与通讯日志。
- `Vision.Calibration`：棋盘格角点识别、亚像素优化与平面单应矩阵求解，依赖固定版本 OpenCvSharp / OpenCV Windows 运行库。
- `Vision.Desktop`：流程列表、图像加载、卡尺交互、参数编辑、上游结果绑定、结果图层和流程导入导出。后台处理与界面线程分离，预览上限 10 FPS。

## 使用

### 多检测流程分页

顶部流程分页可新建、复制、重命名和移除检测流程，最多 32 页。各页独立保存图像源、算子、并行度、标定和最近结果。切换分页只切换编辑与预览，其他运行中的流程继续处理。新建页为空白流程，复制页保留已有算子和配置。

“启动当前流程 / 停止当前流程”控制当前页，“全部启动 / 全部停止”控制所有页的连续检测。“单次运行当前”和“测试当前算子”仍用于调试；单算子测试暂时锁定当前页，其他页继续运行，退出测试后该页恢复原来的连续运行状态。示例和已加载的本地图像也支持连续检测；不同页的本地图像分别保存于内存。

一台物理相机只打开一个采集会话，同一帧可分发给多个绑定它的流程；不同相机的流程同时处理。每个流程独立使用容量为 1 的最新帧队列，同一流程逐帧串行、不同流程并行，沿用全局 CPU 并发预算。慢流程丢弃等待中的旧帧，避免拖住其他流程或无限积压。每页标签显示启停、成功数、处理耗时与帧序号。停止某页不关闭共用相机，顶部采集按钮可独立停止相机采集。

“保存项目”导出全部分页及配置；“导入流程 / 项目”兼容原有单流程 JSON，并把导入内容添加到新分页。配置草稿自动保存在程序目录 `Data/workflows.json`，下次启动恢复分页，运行状态默认停止；图像像素不写入项目文件，本地图像需重新加载。修改相机硬件配置会停止共享采集，其他页面的检测配置仍保留。

验证：`dotnet run --project tools/Vision.Verification -- --verify-workflows`。

启动后自动运行示例：上边缘直线 + 左边缘直线 + 孔圆 → 两线交点、夹角 → 交点到圆心距离。绿色小方块缩放卡尺，绿色圆点旋转，拖动区域移动。右侧编辑后点击“应用参数”或“运行流程”。选择其他算子前请应用右侧参数。

图像预览支持滚轮围绕鼠标位置缩放、工具栏 `− / ＋` 以视口中心缩放、“适应窗口”和“1:1”显示（按屏幕 DPI，一个图像像素对应一个屏幕像素）。中键、右键或空格+左键可在任意位置拖动平移；左键在卡尺外的空白区域也可平移，在卡尺内部和手柄处保持编辑操作。缩放和平移只改变视图，图像坐标与标定参数不变。连续采集的同尺寸新帧保持当前视图；图像尺寸改变或清空后恢复适应窗口。卡尺操作期间忽略滚轮，防止编辑坐标突变。缩放检查：`dotnet run --project tools/Vision.Verification -- --verify-viewport`。

### 单算子运行测试

在左侧选中算子，调整参数或卡尺后，点击右侧“测试当前算子”。测试按钮会先应用当前参数。直线、圆检测只执行本节点；交点、角度、距离计算会在同一张当前图像上重新执行其传递上游依赖，不读取旧结果、不运行无关分支，也不执行下游算子。底层入口为 `WorkflowRunner.RunNodeAsync(image, definition, nodeId, token)`，沿用依赖并行上限和世界坐标转换。

结果列表中标明“目标”和“依赖”，目标行突出显示；参数区显示当前目标的成功 / 失败 / 上游跳过、算子耗时、总测试耗时、边缘点数与拟合误差。图像层只显示本次测试和依赖的结果，旧的完整流程结果不会混入。

实时采集期间测试会锁定当前显示帧，暂停当前流程的实时算子处理及自动结果展示；相机采集与状态更新继续运行。测试后保持图像与结果，方便调整卡尺后再次测试。点击“退出测试 / 恢复实时”、运行完整流程、切换图像源或重新操作采集可退出测试模式。若没有新图像，先加载本地图像或启动相机采集。

运行中可取消；切换所选算子会取消正在进行的单算子测试，修改配置或来源后过期结果会丢弃。正在计算的单个边缘算子会在计算结束后响应取消，不中断原生像素循环。无关分支的未配置输入或循环依赖不会阻止有效单算子测试，目标依赖链中的错误会正常报告。

直线卡尺沿宽度均匀布置采样位置，在矩形的高度方向搜索最大灰度梯度。圆卡尺由多个径向矩形采样区组成，“名义直径”控制位置，“搜索深度”控制径向范围。显示有效边缘点及拟合 RMS 残差。几何算子只能引用列表上游的兼容输出；删除仍被引用的算子会被阻止。

可加载 PNG / BMP / JPEG / TIFF，转换为 Gray8 后进行真实像素计算。单位为像素，角度为 0–90° 的无向锐夹角。保存的 JSON 包含流程和参数，不包含图像。

## 算子并行执行

相机采集并发与算子并行分别调度。`WorkflowRunner.RunAsync` 根据输入引用构建依赖图，无依赖的直线和圆检测可同时执行；几何节点只等待自身输入，不等待无关分支。界面右上方可配置并行上限（1 为串行），该设置随 JSON 流程保存。所有相机共享一个不超过逻辑 CPU 核数的计算预算，每个流程也遵守自己的并行上限，实际并发受就绪节点数、CPU 和线程池调度影响。

依赖等待不占用计算槽位。上游失败时跳过其依赖节点，独立分支继续运行；执行前检查循环依赖，结果按配置顺序返回。结果表显示工作线程 ID、相对流程起点的开始时间与实际计算耗时，便于核对执行重叠。图像和流程快照在单次运行中只读，结果不跨帧复用。停止采集会取消等待中的调度，正在计算的单个算子完成后退出。

运行调度验证（无需第三方测试包）：

```powershell
dotnet run --project tools/Vision.Verification
```

覆盖示例数值、依赖执行顺序、实际并行重叠与上限、串行模式、失败传播、循环依赖、取消、JSON 保存和相机管线启停。

## 当前边界

镜头畸变标定、鲁棒拟合与生产级容差判定尚未接入。核心边缘算法是基础原型，对噪声、遮挡与复杂背景应继续验证；检测失败会返回错误并阻止依赖计算。真实相机的取图、参数范围与触发需要用实际 SDK 和硬件验收。

最初的 HTML 界面仅保留为设计稿，C# 工程入口是 `Vision.Desktop`。

## 相机配置与图像源

1. 点击“相机配置”，选择海康 MVS、华睿 / 大华 MV Viewer 的安装根目录。留空时搜索常见安装目录及程序目录下的 `Sdk/Hikrobot`、`Sdk/Huaray`。
2. 点击“探测已连接相机”。分别调用两家厂商的枚举接口；同时在本机已连接 IPv4 网卡的子网内发送 GigE Vision 发现请求。网络发现可在没有 SDK 时显示支持品牌的 GigE 相机，但正式取图仍需要厂商驱动和 SDK。USB3 发现依赖厂商 SDK。当前仅实现设备发现，不修改 IP 或网卡配置。
3. 选中设备并“加入相机配置”，设置名称、启用状态、曝光（μs）、增益（dB）、目标帧率和连续 / 软件 / 外部 Line1 触发。配置以序列号为优先稳定标识，重复添加会定位已有配置。真实设备与模拟设备明确区分。
4. “测试取图”会连接设备、采集一帧并释放连接。外部触发需要实际信号。模拟相机只使用帧率设置；其他参数用于真实设备。
5. 保存后，在流程左侧“图像输入”下拉框选择已启用相机，再点击“启动已配置相机”。每台相机独立采集，帧分发到所有绑定该来源且已启动的流程。每页可单独启动或点击“全部启动”。切换来源会清除当前页旧结果；未收到新来源图像前不能执行旧图像。

相机目录单独保存到程序目录的 `Data/cameras.json`，流程 JSON 只保存图像源配置 ID。部署时请把程序放到具有写入权限的目录。旧版本流程没有图像源字段时默认使用示例图像。缺失或被禁用的源不会自动替换为另一台相机。

厂商桥接使用实际 SDK 中的结构体定义，支持海康 `MyCamera` 的 `MV_CC_*_NET` .NET 接口库（`MvCameraControl.Net.dll` / `MvCamCtrl.NET.dll`）及华睿 `MVSDK_Net.dll` 的 `IMV_*` 接口。没有打包厂商 SDK，也不自动安装驱动。SDK 不兼容、缺失、参数不支持、设备离线会显示错误。请使用 x64 SDK 和运行库；更换 SDK 根目录建议重启程序。

首版真实设备只接受连续存储的 Mono8 像素，并检查缓冲尺寸后复制为自有托管数组，再释放厂商缓冲。彩色相机若不支持 Mono8 将明确报错，后续可增加厂商像素格式转换。图像源绑定不构成跨相机同步保证。

### 统一搜索可用相机资源

相机配置点击“搜索可用相机资源”，统一汇总以下来源：

- GigE Vision：在本机已连接 IPv4 网卡子网内进行 GVCP 发现。海康、华睿设备可通过现有厂商适配器加入，取图需要对应 SDK。其他品牌也显示在列表中，但会注明只有发现功能且禁止直接加入。
- 厂商 SDK：枚举海康、华睿 / 大华 SDK 能提供的 GigE、USB3 资源，不会因为某个 SDK 缺失而中止其他来源的搜索。
- DirectShow：枚举 Windows 已注册的视频输入设备，包括安装了相应驱动的 USB 摄像头、采集卡和虚拟视频源。使用设备 Moniker 路径绑定，不保存易变化的枚举序号。

搜索结果显示品牌、型号、序列号、协议 / 接口、地址 / 设备路径和可用状态。搜索不打开视频流，因此“已枚举”不保证设备未被其他程序占用。双击行可直接加入，也可以选择行后点击“加入相机配置”；重复资源会定位现有配置。默认不混入模拟设备，可手动勾选显示。不同协议有可能暴露同一物理相机，跨协议不做不可靠的名称去重，请避免同时打开同一硬件的两个接口。

DirectShow 加入后可“测试取图”、保存配置、在流程中选为图像源、参与并行处理和标定。当前支持驱动默认视频格式协商为 RGB24 VideoInfo，并转换为自有 Gray8 图像，正确处理底朝上和4字节行对齐。使用独立 MTA 线程管理过滤器图，帧回调复制厂商缓冲，有界队列丢弃旧帧；取消、断流和退出会停止图并释放 COM 资源。

DirectShow 使用驱动默认曝光、增益和实际硬件帧率；配置中的帧率仅限制输出频率。界面禁用其曝光、增益和触发设置，仅支持连续采集。设备占用、驱动不兼容 RGB24、断流等问题通过测试取图或运行状态报告。SDK 相机仍按原方式设置曝光和触发；SDK 原生取图限制与 DirectShow 协商转换是不同路径。

只读搜索验证：`dotnet run --project tools/Vision.Verification -- --verify-resources`。资源枚举基于 [Microsoft DirectShow 设备枚举机制](https://learn.microsoft.com/en-us/windows/win32/directshow/using-the-system-device-enumerator)，接口封装依赖 DirectShowLib.Standard 2.1.0。

接口依据：[海康 SDK 开发手册（厂商文档镜像）](https://cncu.co.za/FlatCUT-Flatbed-Cutting-Machine/MDR%20Oscillating%20Blade%20CNC%20Router/Hikrobot%20MVS%20%28Machine%20Vision%20Software%29%20STD%204.0.0%20%28221208%29%20Installation/Development/Documentations/Machine%20Vision%20Camera%20SDK%20%28DotNet%29_Developer%20Guide.pdf)、[华睿 C# 开发手册（厂商文档镜像）](https://studylib.net/doc/28288146/%C2%B9%C2%A4%C3%B2%C2%B5%C3%AF%C3%A0%C2%BB%C3%BAsdk%C2%BF%C2%AA%C2%B7%C2%A2%C3%AA%C3%B6%C2%B2%C3%A1-c%23%C3%A6%C2%AA--ver1.1)。GVCP 公开报文字段参考 [Aravis 协议定义](https://github.com/AravisProject/aravis/blob/main/src/arvgvcpprivate.h)；未引入 Aravis 库。

## 通讯配置

主界面点击“通讯配置”。默认类型 `SocketServer`，监听地址 `0.0.0.0`，端口 `10001`，最大客户端 16；默认手动启动，可勾选“程序启动时自动监听”。客户端使用服务器的实际 IP 连接，不能把 `0.0.0.0` 当作远端连接地址。

“保存并启动全部”写入配置并启动已启用的 TCP 监听；各端口分别显示运行状态和在线客户端数量，日志标明端口、连接及收发记录。也可以仅启动或停止选中的端口。关闭配置窗口后服务继续运行，退出主程序时断开连接并释放端口。运行中修改监听参数前需要先停止。端口被占用、IP 无效或配置写入失败会在窗口内显示。

消息协议为 UTF-8 文本，以 LF（`\n`）结束，兼容 CRLF（`\r\n`），处理 TCP 分包和粘包。单条消息最大 64 KiB，超长或无效 UTF-8 会断开该客户端。连接关闭时，没有换行的末尾片段会被丢弃并记录。点击“测试发送”可向手动调试终端广播文本。程序已接入 JSON / PLC 文本流程控制指令，按固定流程编号支持查询、连续启停、单次触发及数值结果回传；自动客户端按请求和响应关联，不应混入调试广播。

通讯配置保存到程序目录的 `Data/communication.json`，与相机及流程文件分别保存。界面保留最近 200 条日志。通讯服务的回归验证通过本机回环连接检查默认值、配置校验、多客户端限制、中文分包和多帧粘包、广播收发、超长限制、停止释放、重新启动及端口占用错误。

## 棋盘格平面标定

在实际测量平面放置棋盘格，通过当前相机采集图像后，点击“棋盘格标定”；也可加载同一相机、同分辨率的棋盘图像。填写内角点列数、行数（不是方格数量）和方格实际边长 mm，点击“识别角点并计算标定”。例如 10×7 个方格对应 9×6 个内角点。

程序识别完整棋盘角点并进行亚像素优化，使用全部对应点拟合图像到世界平面的单应变换，显示像素重投影 RMS。默认 RMS 上限 1 px，超限不能应用。预览显示 O、+X、+Y；可以反转轴并重新计算，必须核对原点方向与现场一致。普通对称棋盘存在方向歧义，软件坐标原点不是自动识别的机器人原点。RMS 是标定点的拟合误差，不代表独立测量精度。

应用后，移动图像区鼠标可查看像素坐标与世界 X/Y（mm）；结果表同时显示像素输出和世界输出。直线使用转换后的边缘点重新拟合；圆使用转换后的边缘点拟合世界圆，输出圆心、半径及 mm 残差；交点、夹角和距离使用上游世界几何重新计算，不使用统一比例简单缩放。世界圆的较大拟合残差提示形状不满足圆模型，应核对标定与检测。

标定嵌入流程 JSON，也可单独导入导出。标定绑定图像源 ID 和分辨率，来源或尺寸不匹配时保留像素结果并拒绝世界输出。单平面映射只适用于与棋盘格相同的测量平面，不能恢复任意物体的三维 Z。相机、焦距、分辨率、裁剪、图像方向或测量平面变化后须重新标定；相同尺寸不能检测裁剪或机械移动。棋盘角点覆盖范围之外属于外推，需独立验证。

首版没有估计内参和镜头畸变，适用于畸变已较小或已校正的固定工业成像条件。算法依据 [OpenCV 标定与平面变换文档](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。首次构建需从 NuGet 还原 OpenCvSharp4 和 Windows 原生运行库，使用 x64 环境。

## 无重叠双相机融合标定（二维码长棋盘）

针对约 200×1000 mm 的标定板、两台相机分别观察两端的场景，点击“双相机融合”。该功能建立共享二维物理坐标系，不依赖两幅图像重叠，也不使用相机“约 1 米”的间距作为数值。两台相机必须观察同一块固定且与测量面共面的板。

已确认码文为从 1 开始的 `(行,列)`，格子 10×10 mm，二维码位于格子中心，每个视野至少 4 个不共线二维码。解析兼容中英文括号、逗号，例如 `(1,2）`。定义板编号左上角为原点，X 沿列、Y 沿行，则二维码中心 `X=(列−0.5)×10`，`Y=(行−0.5)×10` mm。例如第一行第二列为 `(15,5) mm`。默认整板列数 20、行数 100；如果实际板把长边定义为列方向，请按实际编号调整为列数 100、行数 20。不要单独旋转其中一个相机的世界轴。

操作步骤：

1. 在相机配置里启用两台相机，启动采集获取静态板图像，或分别准备同分辨率相机图像。
2. 打开“双相机融合”，选择相机 A，加载其图像或使用最近采集帧；点击“识别二维码”。
3. 核对二维码原文和中心位置，确认所选 `(行,列)` 格式、10mm 方格、整板行列数以及“位于格子中心”，再点击按格式填写坐标。未解码的码或格式错误的坐标不自动参与拟合。
4. 每台至少 4 点（建议 6 点以上并覆盖二维视野），点击计算。可把部分额外点勾选为“检验”，这些点不参与求解，报告它们的独立毫米误差。所有点参与拟合时的 RMS 不能代表独立测量精度。
5. 选择相机 B 重复操作，两台使用相同世界坐标系 ID，默认 `board-main`。最后保存并应用，再保存流程；也可单独导出、导入融合配置。

每个相机保存自己的图像到世界矩阵、分辨率、控制点及坐标系 ID。流程切换图像源时自动选择相应标定。旧的单相机标定文件仍兼容。`FusionCalibration.CrossCameraDistance` 可计算同一融合坐标系中的两相机点间距离，拒绝不同坐标系。各流程可分别绑定不同相机并同时运行，在分页中查看各自结果；这不包含图像拼接或多相机硬件同步。

普通重复棋盘无法单凭局部纹理确定整板索引，本模块使用二维码提供的绝对行列号。若码不在格子中心，则不可直接使用码中心；可点击实际棋盘角点并输入其已知毫米坐标。软件拒绝不足四点、共线、重复点、无效坐标和重投影超限。二维码识别会给出投影对角线交点作为码中心，避免透视下使用四角算术平均造成偏移。

无重叠时没有共同可见点可直接检查两机一致性，需要用跨视野已知长度或独立检验点进行现场验收。当前没有镜头畸变校正或三维高度恢复，相机/镜头/测量平面变化后应重标定。最近帧缓存不是同步采图保证。QRCoder 用于 QR 生成，OpenCV 用于 QR 定位和解码；ZXing 用于 Data Matrix 生成与识别，复杂棋盘背景下使用局部候选区域辅助识别。

## 稀疏编码棋盘格生成器

点击“棋盘格生成器”，可设置方格行列数、实际边长 mm、外围白边、QR Code / Data Matrix ECC200、QR 纠错等级、起始行列、行间隔和列间隔、末行末列补码，以及码整体占格子比例（包含静区）。默认 100 行、20 列、10 mm 方格，对应棋盘主体 200×1000 mm；外围白边各 10 mm，导出总尺寸为 220×1020 mm。

默认从第 1 行第 1 列开始，每隔 10 行、6 列放码，并在末行末列补码，共 55 个码（2000 格的 2.75%）。二维码类型和纠错等级可能改变码元数量；代码整体始终居中，不覆盖方格边界，保留白色静区。棋盘黑格中的码使用白底，因此会改变格子中央纹理，普通棋盘角点检测应按实际拍摄图像验证；融合标定使用码中心和绝对格子索引。

编码文本为 `(行,列)`，从 1 开始，坐标原点位于棋盘主体左上角，外侧白边不计入世界坐标。码中心世界坐标为 `X=(列−0.5)×边长`、`Y=(行−0.5)×边长` mm。稀疏程度应结合相机视野调整，保证每个相机看到至少 4 个不共线的码，建议 6 个以上；生成器无法在未知相机视野时保证可见数量。

支持导出 SVG 矢量板和带实际 DPI 元数据的 PNG。两种格式都会同时导出同名 `.board.json`，可重新载入生成器，或在“双相机融合”中点击“导入板参数”自动填写行列数与方格尺寸。融合标定支持这两种编码。PNG 最大 1 亿像素，高 DPI 大板请使用 SVG。预览仅供排版，打印时必须选择实际大小 / 100%，关闭适应纸张，打印后实测方格边长。

最小码元的毫米尺寸和 PNG 预估像素数会在界面显示。码元过小时应提高 DPI、增大格子或码占比，并用实际相机验证；提高纠错等级不会补偿不足的成像分辨率。示例文件可通过验证程序输出：

```powershell
dotnet run --project tools/Vision.Verification -- --verify-boards artifacts/board-examples
```

验证生成板的两种编码能被读回、中心位置与格子坐标一致、稀疏分布与边缘补点、SVG 毫米尺寸、参数保存及超大栅格导出限制。

## 外部 C# / PLC 控制

通讯配置中 SocketServer 默认端口 `10001`，支持 UTF-8 JSON 和 PLC 的 ASCII Socket Send/Receive 文本命令。可勾选“启用 Modbus TCP”（默认端口 `502`，Unit ID `1`），两种接口共用检测流程。流程分页中的“外部编号”为持久化的 1–32 固定编号，可在停止状态下修改，与页面位置无关。

单次检测等待请求后到达程序的新相机帧；静态示例和文件源使用当前图像。单次结果锁存供外部设备读取，连续预览不会把其他帧的测量替换到该请求中。响应包含忙碌、无图像、超时、配置变化及相机错误。当前检测成功表示所有算法执行成功，尚未加入产品尺寸公差判定。

完整命令、Modbus 寄存器表和握手步骤见 [外部设备接入](docs/外部设备接入.md)，C# 可运行示例见 `samples/Vision.ExternalClient`。

验证命令：

```powershell
dotnet run --project tools/Vision.Verification -- --verify-external
dotnet run --project tools/Vision.Verification -- --verify-desktop-control artifacts/net8-external-control/Vision.Desktop.exe
```

第二项会复制程序到独立测试目录，启动测试用 WPF 进程，通过真实 TCP 驱动模拟相机和检测流程，结束后只终止自己创建的测试进程，不修改用户配置。
### SocketServer 多端口与流程绑定

通讯配置可添加最多 32 条 SocketServer 端口，分别设置名称、监听 IP、端口、连接上限及绑定检测流程。默认保留 `10001` 通用控制端口，也可把它绑定到指定流程；例如 `10002 → 流程一`、`10003 → 流程二`。绑定保存流程固定 ID，切换分页或修改编号不会把端口改绑到其他流程；删除流程后该端口明确返回绑定失效。

选中端口可独立启停和测试发送，其他端口继续工作。端口占用只使该端口启动失败，其他可用端口继续监听。运行中的端口需先停止再修改配置。日志按端口区分，检测响应只返回请求所在的连接。通用端口继续使用流程编号，绑定端口可省略编号：

```text
DATA,batch001,PART-A
TRIGGER,run001,5000
RESULT,3,value001
```

以上每行均需追加 LF。`DATA` 是附加业务文本，允许条码、批次等数据（最多 8192 UTF-8 字节）；单次检测结果的 `inputData` 回传对应文本。也可在 JSON `run_once` 中直接携带 `data`，将数据与触发合为一个请求。附加文本不自动修改图像、卡尺或几何参数。

绑定端口的可运行 C# 示例：

```powershell
dotnet run --project samples/Vision.ExternalClient -- 127.0.0.1 10002 run_once --bound --data PART-A
```

多端口专项验证：`dotnet run --project tools/Vision.Verification -- --verify-ports`。完整协议见 [外部设备接入](docs/外部设备接入.md)。
